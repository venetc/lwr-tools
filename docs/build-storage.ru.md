# Хранение билдов

[English](build-storage.en.md) · **Русский**

Билды калькуляторов билдов переживают рефреш и переоткрытие: они сохраняются в `localStorage` и синхронизируются между открытыми вкладками. У каждого калькулятора свой префикс и свой список: `lwr-tools.biosoldier-builds.v1.` и `lwr-tools.shiv-builds.v1.`; ключи и записи ниже показаны для биосолдат, у SHIV они такие же.

## Ключи

```
lwr-tools.biosoldier-builds.v1.order         → ["id1", "id2", …]
lwr-tools.biosoldier-builds.v1.build.<id>    → { "code": "AQx…", "readonly": false }
```

- `code` — [share-код](share-codes.ru.md) билда: класс, перки и имя. Его формат сам обеспечивает чтение старых кодов, поэтому запись добавляет к нему только лок.
- По ключу на билд: вкладка меняет только те записи, которые затронула, и не перезаписывает правки других вкладок целым снимком.
- `order` — порядок показа. Если `order` нет, значит, ещё ничего не сохраняли, и страница показывает дефолтные билды. `[]` означает, что пользователь удалил все.
- Префикс `lwr-tools.` обязателен: на GitHub Pages все проекты `<user>.github.io` делят одно хранилище.

Код: [`shared/lib/stored-list`](../src/shared/lib/stored-list/README.ru.md) (загрузка, сохранение, синхронизация вкладок, задержки), `features/manage-builds` (операции списка билдов: переименование, замок, импорт, замена, удаление), `features/share-build`: `config/constants.ts` (схема записи) и `model/stored-build.ts` (запись билда ↔ билд через share-код) и в странице каждого калькулятора (`pages/biosoldier-builds`, `pages/shiv-builds`) `config/constants.ts` (ключи) и стор `model/biosoldier-builds.ts` / `model/shiv-builds.ts` (билды по умолчанию, правила дерева).

## Загрузка

- Сначала id из `order`, затем записи билдов, которых в нём нет: они идут в конец, в порядке хранилища. Такие записи появляются, когда две вкладки добавляют билды одновременно.
- id из `order` без записи пропускаются.
- Запись, которую не удалось разобрать (JSON, форма, share-код), пропускается и остаётся в хранилище: её может прочитать более новая версия приложения.
- Битый `order` считается `[]`, записи всё равно восстанавливаются.
- У дефолтных билдов фиксированные id (`default-<classId>` у биосолдат, `default-shiv` у SHIV), и они сохраняются сразу. Поэтому вкладки, открытые впервые одновременно, пишут одни и те же записи.

## Сохранение

- Экшены стора помечают изменённый билд, а при добавлении или удалении — и порядок. За состоянием никто не следит.
- Изменения сохраняются через 300 мс после последнего, при непрерывной правке не реже раза в 2 с, а при скрытии или закрытии страницы — сразу (`visibilitychange`, `pagehide`).
- Билд сохраняется заново из текущего состояния, запись удалённого билда удаляется.

## Синхронизация вкладок

Вкладка получает событие `storage` об изменениях, сохранённых другими вкладками, и применяет их напрямую, не через экшены. Поэтому обратно они не сохраняются.

- Запись билда изменилась → билд заменяется на месте, панель не перемонтируется. Новая запись → билд добавляется в конец. Запись удалена → билд удаляется.
- `order` изменился → билды переставляются. Билды этой вкладки, которых в нём нет, остаются в конце, и тогда объединённый порядок сохраняется.
- Входящее изменение билда отменяет ожидающее сохранение этого билда в текущей вкладке.

## Смена формы записи

Ключи и форма записи не меняются. Новая форма получает новую версию в префиксе (`v2`): загрузка читает `v2`, а если его нет — читает `v1` и сохраняет как `v2`.

## Ограничения

- Один и тот же билд правят в двух вкладках одновременно: побеждает последнее сохранение.
- Очистка хранилища из другой вкладки игнорируется. Текущая вкладка запишет свои записи заново при следующем изменении.
- Имя длиннее 31 байта UTF-8 обрезается share-кодом, поэтому после рефреша вернётся обрезанным.
