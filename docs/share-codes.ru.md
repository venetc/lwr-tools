# Коды билдов солдат

[English](share-codes.en.md) · **Русский**

Выданный код должен открываться всегда: коды, сохранённые игроками, мы обновить не можем.

## Устройство

```
format (8) | секция … | 0 (5) | padding | crc (8)   → base64url
секция = id (5) | length (9) | поля
```

- Секции идут по возрастанию id, каждая не больше одного раза; `0` завершает список.
- Неизвестные секции пропускаются по длине.
- Прочитанная секция должна закончиться ровно на своей длине, иначе код невалиден; пропущенные секции не проверяются.
- `decodeSoldierBuild(code, parts)` читает только запрошенные части, остальные получают значения по умолчанию.

Код: `shared/lib/share-code` (биты, секции, CRC, base64url) и фича `features/share-build`: `config/share-code-format.ts` (номера форматов), `config/soldier-build-section.ts` (id секций), `model/soldier-build-code.ts` (поля), `model/types.ts` (`SoldierBuildPart`). Поиск по `code` даёт `entities/soldier`.

## Секции

| Секция | id | Поля | Пишется |
|---|---|---|---|
| `TALENTS` | 1 | `class` 5 · `count` 3 · `ability` 8 × count | всегда |
| `NAME` | 2 | `nameLength` 5 · UTF-8 | если имя отличается от названия класса |

`count` — число талантов, выбранных сверх выданного; абилки идут по рангам снизу вверх. Выданный талант при импорте берётся из текущего дерева.

## Нумерация

Коды хранят номера `code` абилок и классов, а не позиции в дереве, поэтому деревья можно менять свободно.

- Новая запись: максимальный `code` + 1.
- Существующий `code` не менять.
- `code` удалённой записи не переиспользовать; лучше записи не удалять.
- `0` не выдаётся: у абилок и классов это «неизвестно», у секций — конец списка.

То же для `SOLDIER_BUILD_SECTION` и `SHARE_CODE_FORMAT`.

Пример: новая абилка, максимальный `code` — 73.

1. `abilities.json`: `"deadeye": { "code": 74, "name": "Deadeye", "description": "…" }`.
2. `config/constants/ability-icons.ts`: иконка `deadeye` в `ABILITY_ICON`.
3. `classes.json`: `"deadeye"` на ранге класса.
4. `npm test`.

## Безопасные правки

Добавлять, переносить, переставлять и убирать абилки в деревьях; менять названия, описания, иконки; переименовывать id (с прежним `code`); добавлять классы.

Если абилку на ранге заменили другой, старую запись оставить. Старые коды откроются, ранг будет пройден без выбранной клетки.

## Ломающие правки

| Правка | Старые коды |
|---|---|
| сменить или переиспользовать `code` | покажут не ту абилку |
| удалить запись | «Invalid code» |
| изменить поля секции или их ширины | «Invalid code» или неверные данные |
| изменить разметку секций, CRC или base64url | недействительны все коды |

Поля секции меняются только новой секцией:

1. Добавить в `SOLDIER_BUILD_SECTION` следующий id с суффиксом версии.
2. К имени текущего чтения секции добавить суффикс версии; её запись удалить.
3. Написать новые запись и чтение; `decodeSoldierBuild` читает ту из двух секций, что есть в коде.

Чтение старых секций остаётся навсегда. Сама разметка секций меняется только новым номером в `SHARE_CODE_FORMAT`.

Пример: в `TALENTS` добавляется поле, максимальный id секции — 2.

1. `SOLDIER_BUILD_SECTION`: `TALENTS_V2: 3`.
2. `soldier-build-code.ts`: `readTalents` → `readTalentsV1`, `writeTalents` удалить.
3. Новые `writeTalents` / `readTalents`; `encodeSoldierBuild` пишет `TALENTS_V2`.
4. `decodeSoldierBuild`: `TALENTS` → `readTalentsV1` с новым полем по умолчанию, `TALENTS_V2` → `readTalents`.

## Новая часть

1. Добавить в `SOLDIER_BUILD_SECTION` следующий id.
2. Написать запись и чтение в `soldier-build-code.ts`; `encodeSoldierBuild` пишет секцию, только если у билда есть эта часть.
3. Добавить часть в `SoldierBuildPart`; `decodeSoldierBuild` читает секцию, только если часть запрошена, иначе даёт значение по умолчанию.

Пример: офицерское дерево, максимальный id секции — 2.

1. `SOLDIER_BUILD_SECTION`: `OFFICER: 3`.
2. `writeOfficer` / `readOfficer`; у не-офицера секции нет.
3. `SoldierBuildPart`: `'officer'`; без секции или без части у билда нет офицерского дерева.

## Проверки

`npm test` проверяет диапазон и уникальность `code`, id и циклы `grants`, а также сам формат кодов; хук перед пушем запускает его вместе с `vue-tsc` и линтером.

Смену или переиспользование `code` ловит только ревью.
