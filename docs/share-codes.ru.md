# Коды билдов биосолдат

[English](share-codes.en.md) · **Русский**

Выданный код должен открываться всегда: коды, сохранённые игроками, мы обновить не можем.

У кодов билдов SHIV то же устройство и правила: [коды билдов SHIV](shiv-share-codes.ru.md).

## Устройство

```
format (8) | секция … | 0 (5) | padding | crc (8)   → base64url
секция = id (5) | length (9) | поля
```

- Секции идут по возрастанию id, каждая не больше одного раза; `0` завершает список.
- Неизвестные секции пропускаются по длине.
- Прочитанная секция должна закончиться ровно на своей длине, иначе код невалиден; пропущенные секции не проверяются.
- `decodeBiosoldierBuild(code, parts)` читает только запрошенные части, остальные получают значения по умолчанию.

## Результат декодирования

Декодер возвращает `{ status: 'decoded', build }` или причину неудачи:

- `{ status: 'other-unit', unit }` — CRC и заголовок валидны, но `format` принадлежит билдам другого юнита (`SHARE_CODE_FORMAT_UNIT`: `1` Biosoldier, `2` SHIV). Импорт показывает toast «This is a <unit> build code» и оставляет форму открытой с кодом.
- `{ status: 'invalid' }` — всё остальное: битый код, неизвестный формат, отсутствующая или битая секция, класс другого формата, перк не из своего ранга дерева класса. Импорт показывает «Invalid code» под полем.

Сохранённый билд, чей код не декодируется, при загрузке пропускается.

Код: `shared/lib/binary-code` (заголовок, секции, CRC; поверх `shared/lib/bit-stream`, `base64-url` и `crc8`) и фича `features/share-build`: `config/constants.ts` (номера форматов и их юниты, id секций, ширины полей), `model/share-code.ts` (результат декодирования, открытие кода ожидаемого формата), `model/soldier-build-code.ts` и `model/shiv-build-code.ts` (поля и части билда; `soldierBuildCodec` собирает кодер и декодер формата солдат по его классам по коду, `encodeBiosoldierBuild` / `decodeBiosoldierBuild` — его пара для формата 1), `model/stored-build.ts` (записи хранилища поверх share-кода). Поиск по `code` (абилки, классы каждого формата солдат, перки SHIV) дают `entities/soldier` и `entities/shiv`. Фича обслуживает обе страницы калькуляторов и остаётся отдельным слайсом: формат меняется по своим причинам, у него свои тесты и доки.

## Секции

| Секция | id | Поля | Пишется |
|---|---|---|---|
| `PERKS` | 1 | `class` 5 · `count` 3 · `ability` 8 × count | всегда |
| `NAME` | 2 | `nameLength` 5 · UTF-8 | если имя отличается от названия класса |

`count` — число перков, выбранных сверх базового; абилки идут по рангам снизу вверх. Базовый перк при импорте берётся из текущего дерева.

## Нумерация

Коды хранят номера `code` абилок и классов, а не позиции в дереве, поэтому деревья можно менять свободно.

- Новая запись: максимальный `code` + 1.
- Существующий `code` не менять.
- `code` удалённой записи не переиспользовать; лучше записи не удалять.
- `0` не выдаётся: у абилок и классов это «неизвестно», у секций — конец списка.

То же для `SOLDIER_BUILD_SECTION` и `SHARE_CODE_FORMAT`.

Пример: новая абилка, максимальный `code` — 73.

1. `abilities.json`: `"deadeye": { "code": 74, "name": "Deadeye", "description": "…" }`.
2. `config/constants/ability-icons.ts`: иконка `deadeye` в `ABILITY_ICON`.
3. `biosoldier-classes.json`: `"deadeye"` на ранге класса.
4. `npm test`.

## Безопасные правки

Добавлять, переносить, переставлять и убирать абилки в деревьях; менять названия, описания, иконки; переименовывать id (с прежним `code`); добавлять классы.

Если абилку на ранге заменили другой, старую запись оставить. Старые коды откроются, ранг будет пройден без выбранной клетки.

## Ломающие правки

| Правка | Старые коды |
|---|---|
| сменить или переиспользовать `code` | покажут не ту абилку |
| удалить запись | «Invalid code» |
| изменить поля секции или их ширины | «Invalid code» или неверные данные |
| изменить разметку секций, CRC или base64url | недействительны все коды |

Поля секции меняются только новой секцией:

1. Добавить в `SOLDIER_BUILD_SECTION` следующий id с суффиксом версии.
2. К имени текущего чтения секции добавить суффикс версии; её запись удалить.
3. Написать новые запись и чтение; `decode` из `soldierBuildCodec` читает ту из двух секций, что есть в коде.

Чтение старых секций остаётся навсегда. Сама разметка секций меняется только новым номером в `SHARE_CODE_FORMAT`.

Пример: в `PERKS` добавляется поле, максимальный id секции — 2.

1. `SOLDIER_BUILD_SECTION`: `PERKS_V2: 3`.
2. `soldier-build-code.ts`: `readPerks` → `readPerksV1`, `writePerks` удалить.
3. Новые `writePerks` / `readPerks`; `encode` из `soldierBuildCodec` пишет `PERKS_V2`.
4. `decode` из `soldierBuildCodec`: `PERKS` → `readPerksV1` с новым полем по умолчанию, `PERKS_V2` → `readPerks`.

## Новая часть

1. Добавить в `SOLDIER_BUILD_SECTION` следующий id.
2. Написать запись и чтение в `soldier-build-code.ts`; `encode` из `soldierBuildCodec` пишет секцию, только если у билда есть эта часть.
3. Добавить часть в `SoldierBuildPart`; `decode` из `soldierBuildCodec` читает секцию, только если часть запрошена, иначе даёт значение по умолчанию.

Пример: офицерское дерево, максимальный id секции — 2.

1. `SOLDIER_BUILD_SECTION`: `OFFICER: 3`.
2. `writeOfficer` / `readOfficer`; у не-офицера секции нет.
3. `SoldierBuildPart`: `'officer'`; без секции или без части у билда нет офицерского дерева.

## Проверки

`npm test` проверяет диапазон и уникальность `code`, id и циклы `grants`, а также сам формат кодов; хук перед пушем запускает его вместе с `vue-tsc` и линтером.

Смену или переиспользование `code` ловит только ревью.
