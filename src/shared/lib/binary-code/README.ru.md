# binary-code

[English](README.en.md) · **Русский**

Компактный бинарный код для данных, которые пользователи копируют и вставляют: короткий, проверяется на опечатки и читается будущими версиями приложения.

У кода есть номер формата и список секций. Какие секции писать и что в них лежит, решает владелец данных; модуль отвечает за рамку вокруг них: id и длины секций, контрольную сумму и текстовый вид.

## Раскладка

```
format (8) | section … | 0 (5) | padding | crc8 (8)   → base64url
section = id (5) | length (9) | fields
```

- `format` — какие данные лежат в коде; читатель проверяет его до чтения секций.
- Перед каждой секцией — её id и длина в битах, поэтому читатель, не знающий секцию, её пропускает.
- Id `0` завершает список; последний байт дополняется нулями.
- `crc8` покрывает все байты перед ним и ловит опечатки и обрезанные коды.

## Использование

```ts
const code = encodeBinaryCode(FORMAT, [
  { id: SECTION.TALENTS, write: (writer) => {
    writer.writeUint(classCode, 5);
    writer.writeUint(talentCount, 3);
  } },
  { id: SECTION.NAME, write: writer => writer.writeString(name, 5) },
]);

const opened = openBinaryCode(code);

if (!opened || opened.format !== FORMAT) return null;

const reader = opened.sections.get(SECTION.TALENTS) ?? null;

if (!reader) return null;

const classCode = reader.readUint(5);
const talentCount = reader.readUint(3);

if (!reader.isComplete) return null;
```

## API

| Функция | Аргументы | Результат |
|---|---|---|
| `encodeBinaryCode(format, sections)` | номер формата 0–255; секции в любом порядке, у каждой `id` и `write(writer)`, которая пишет поля в новый `BitWriter` | код base64url; `null`, если секция длиннее 511 бит |
| `openBinaryCode(code)` | текст кода; пробелы по краям игнорируются | `{ format, sections }`: `BitReader` на каждый id секции; `null`, если код невалиден |

Типы: `BinaryCodeSection`, `OpenedBinaryCode`; `BitReader` и `BitWriter` реэкспортируются из `bit-stream`.

## Проверки

`openBinaryCode` возвращает `null`, если:

- текст не base64url или короче двух байтов;
- не сходится CRC;
- id секций не строго по возрастанию (заодно исключает дубли);
- секция или завершающий id выходят за конец данных;
- после завершающего id есть целые байты — допустим только паддинг последнего байта.

Поля секций модуль не проверяет: он их не знает. После чтения секции вызывающий проверяет `reader.isComplete` — секция прочитана ровно до конца. Недостающее или лишнее поле делает секцию невалидной.

## Развитие формата

- Новый вид данных — новая секция со следующим id; старые читатели её пропускают.
- Поля существующей секции не меняются: изменённая секция получает новый id, а читатель старой остаётся.
- Сама рамка (ширины id и длины, CRC, base64url) меняется только с новым номером формата.
- Номера форматов и id секций не переиспользуются.

Как это применяется к билдам солдат: [docs/share-codes](../../../../docs/share-codes.ru.md).

## Ограничения

| Что | Предел |
|---|---|
| номер формата | 0–255 |
| id секции | 1–31 |
| длина секции | 511 бит; с более длинной секцией `encodeBinaryCode` возвращает `null` — владелец держит секции в пределе |
