# local-storage

[English](README.en.md) · **Русский**

Доступ к `localStorage`, который никогда не бросает исключений. Хранилище бывает недоступно (приватный режим, данные сайта заблокированы браузером или настройками) или переполнено. Тогда исключение бросает любое обращение, включая чтение самого `localStorage`. Здесь каждый такой случай превращается в пустой результат.

## Использование

```ts
writeLocalStorage('app.settings', JSON.stringify(settings));

const value = readLocalStorage('app.settings');

if (value === null) return defaults;

const keys = localStorageKeys('app.drafts.');

keys.forEach(removeLocalStorage);
```

## API

| Функция | Аргументы | Результат |
|---|---|---|
| `readLocalStorage(key)` | ключ | сохранённое значение; `null`, если ключа нет или хранилище недоступно |
| `writeLocalStorage(key, value)` | ключ, значение | `true`, если записано; `false`, если хранилище недоступно или переполнено |
| `removeLocalStorage(key)` | ключ | `true`, если удалён или его не было; `false`, если хранилище недоступно |
| `localStorageKeys(prefix)` | префикс ключа | ключи с этим префиксом; `[]`, если хранилище недоступно |

## Поведение

- Отсутствующий ключ и недоступное хранилище читаются одинаково — как `null`: вызывающий в обоих случаях берёт значения по умолчанию.
- Порядок ключей в `localStorageKeys` задаёт браузер, он не гарантирован. Если порядок важен, храните его в данных.
- Значения — только строки, сериализация на стороне вызывающего.

## Ограничения

- Хранилище одно на весь origin. На GitHub Pages его делят все проекты `<user>.github.io`, поэтому ключам нужен префикс приложения.
- Около 5 МБ на origin, доступ синхронный: подходит для небольших записей, не для объёмных данных.
- Изменения из других вкладок приходят событием `storage` на `window`. Модуль его не слушает.
