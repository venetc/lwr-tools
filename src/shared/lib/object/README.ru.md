# object

[English](README.en.md) · **Русский**

Типы и типизированные операции для статичных объектов, записанных в коде, — словарей контента, иконок, настроек.

`Object.entries` и подобные типизируют ключи как `string`: в рантайме у объекта может быть больше ключей, чем в его типе. У объектов, записанных в коде, такого не бывает, и эти помощники сохраняют тип ключей.

## Использование

```ts
const ranks = typedEntries(SOLDIER_RANK_CONTENT).map(([rankId, content]) => ({ id: rankId, name: content.name }));
// rankId: SoldierRankId, not string
```

Константы не меняются в рантайме, и `DeepReadonly` фиксирует это в типе:

```ts
export const ARMORS: DeepReadonly<Armor[]> = typedEntries(ARMOR_CONTENT).flatMap(armorsFromEntry);
// ARMORS.push(…) и ARMORS[0].hp = 1 — ошибки типов
```

## API

| Функция / тип | Аргументы | Результат |
|---|---|---|
| `typedEntries(object)` | статичный объект | `[ключ, значение][]` с сохранённым типом ключей, в порядке ключей объекта |
| `DeepReadonly<Value>` | тип статичного значения | тот же тип, где все поля и массивы readonly на любой глубине |

## DeepReadonly

- Примитивы (и брендированные строки вида `string & {}`) и функции — компоненты, колбэки — остаются как есть.
- Только на уровне типов: в рантайме ничего не замораживается.
- `Map` превращается в тип объекта: словари объявляются как `ReadonlyMap<Key, Value>`.
- Для литерала в коде то же даёт `as const satisfies Type`, сохраняя литеральные типы.
- Readonly-массив нельзя передать туда, где ждут изменяемый: такие параметры и поля объявляются `readonly T[]`, либо получатель берёт копию.

## Только для статичных объектов

Для рантайм-данных — разобранного JSON, ввода пользователя, ответов API — лишние ключи возможны, и сохранённый тип врал бы. Рантайм-коллекции ключ → значение — это `Map`.
