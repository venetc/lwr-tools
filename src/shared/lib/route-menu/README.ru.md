# route-menu

[English](README.en.md) · **Русский**

Меню ссылок, собранные из записей маршрутов: маршрут попадает в меню по `meta.title`, поэтому новый маршрут сам появляется во всех меню своего уровня.

## Использование

```ts
const items = routeMenuItems(router.options.routes);
// [{ label: 'Home', to: '/home' }]
```

```ts
const { parentTitle, items } = useSiblingRoutes();
// соседние страницы под заголовком их родительского маршрута
```

```ts
const { items } = useTopLevelRoutes();
// страницы верхнего уровня приложения, для меню главной
```

## API

| Функция / тип | Аргументы | Результат |
|---|---|---|
| `routeMenuItems(records)` | записи маршрутов | `RouteMenuItem[]` записей с `meta.title`, в их порядке |
| `useSiblingRoutes()` | — | `{ parentTitle, items }`: computed-заголовок родительского маршрута и пункты меню его детей |
| `useTopLevelRoutes()` | — | `{ items }`: пункты меню маршрутов верхнего уровня роутера |
| `RouteMenuItem` | — | `{ label, to }` |

## Поведение

- Записи без `meta.title` пропускаются: у индексной страницы раздела обычно своего заголовка нет, до неё доходят через родителя.
- Для маршрута верхнего уровня `useSiblingRoutes` даёт пустой заголовок и пустой список.

## Ограничения

- Пункты ведут на пути так, как они записаны в записях, поэтому нужны абсолютные пути; относительный путь ребёнка на страницу не приведёт.
- `useTopLevelRoutes` собирает пункты один раз: маршруты, добавленные в роутер позже, в список не попадут.
- Только один уровень: дети детей в список не попадают.
