# stored-list

[English](README.en.md) · **Русский**

Упорядоченный список элементов, который переживает перезагрузку и синхронизируется между открытыми вкладками. Каждый элемент хранится отдельной записью в `localStorage`, поэтому вкладка пишет только то, что изменила, и не затирает правки других вкладок целым снимком.

## Использование

```ts
const notes = useStoredList<Note>({
  orderKey: 'app.notes.v1.order',
  itemKeyPrefix: 'app.notes.v1.note.',
  serialize: note => ({ text: note.text }),
  parse: (id, record) => (isNoteRecord(record) ? { id, text: record.text } : null),
  defaultItems: () => [{ id: 'welcome', text: 'Hello' }],
});

notes.addItem({ id: createId(), text: '' });

const note = notes.getItem(id);

if (!note) return;

note.text = text;
notes.markItemChanged(id);
```

Вызывать внутри setup компонента или setup-стора: модуль слушает события window и document, пока жив этот scope.

## API

`useStoredList(options)`:

| Опция | Значение |
|---|---|
| `orderKey` | ключ порядка: JSON-массив id; его отсутствие значит, что ещё ничего не сохранялось |
| `itemKeyPrefix` | префикс ключа записи элемента, за ним идёт id |
| `serialize(item)` | запись элемента, готовая к JSON; `null` оставляет прежнюю запись |
| `parse(id, record)` | элемент из разобранной записи; `null` для битой записи |
| `defaultItems()` | элементы, которые показываются и сохраняются, пока ничего не сохранено |

| Результат | Значение |
|---|---|
| `items` | computed: элементы по порядку |
| `getItem(id)` | элемент, изменяемый на месте; `null`, если его нет |
| `addItem(item)` | добавляет в конец и сохраняет |
| `removeItem(id)` | удаляет элемент и его запись |
| `markItemChanged(id)` | сохраняет элемент после правки на месте |

`LockableItem<Data>` — данные с `id` и `readonly`: форма элемента, который пользователь может запереть от правок. Сам список `readonly` не читает, проверяет вызывающий перед правкой.

## Поведение

- Загрузка: сначала id из порядка, затем записи, которых в нём нет, — в порядке хранилища. Id без записи пропускаются; запись, которая не JSON или которую отверг `parse`, пропускается и остаётся в хранилище; битый порядок считается `[]`.
- Ничего не сохранено: `defaultItems()` показываются и сразу сохраняются. Давайте им фиксированные id, чтобы вкладки, открытые одновременно, писали одни и те же записи.
- Сохранение: через 300 мс после последней правки, не реже раза в 2 с при непрерывном редактировании и сразу, когда страница скрыта или закрыта (`visibilitychange`, `pagehide`). Пишутся только отмеченные записи и порядок.
- Другие вкладки: их сохранённые правки приходят событием `storage` и применяются напрямую, без обратного сохранения. Изменённая запись заменяет элемент на месте, новая добавляется в конец, удалённая удаляет элемент. Изменённый порядок переставляет элементы; отсутствующие в нём остаются в конце, и объединённый порядок сохраняется. Входящая правка элемента отменяет отложенное сохранение этого элемента в текущей вкладке.

## Ограничения

- Один элемент правят в двух вкладках одновременно: побеждает последнее сохранение.
- Очистка хранилища из другой вкладки игнорируется; текущая вкладка снова запишет свои записи при следующей правке.
- Ключам нужен префикс приложения: у origin одно хранилище на всех (см. `local-storage`).
- Форма записи — забота вызывающего: новая форма требует новых ключей (например, новой версии в префиксе) и миграции на его стороне.
